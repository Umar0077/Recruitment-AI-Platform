# Baseline before application changes

Captured 2026-11-19 local time on Windows, i5-12450H, 16 GB RAM, Node 23.10.0, Next 15.5.29, installed headless Chrome 136, 1440×1000; no artificial CPU/network throttling. Existing fictional Demo Mode only; no real authentication or candidate requests. Development uses port 3200 and its own output directory; production uses port 3300. Both use the installed Next CLI (npm/PowerShell dropped forwarded port flags). Build uses the supported `npm run build` script.

- Development first admin login: 45.41 s including network-idle wait; server reported 41.1 s compilation, 43.15 s HTTP request. First Candidates 4.43 s, Analytics 5.81 s; warmed routes still show development overhead. These are not production figures.
- Production first Candidates 567 ms, Analytics 1,675 ms; warmed Candidates 163 ms, Analytics 179 ms, Dashboard 59 ms. Route timings are click to first animation frame containing destination content, not final data freshness or field INP.
- Production first Candidates and Analytics replace old content during loading. Development candidate instructions, consent and status detach the existing header. Ordinary navigation has no immediate feedback until routing/loading begins (often hundreds or thousands of milliseconds).
- Static analysis confirms a fixed 350 ms Demo Mode login delay, candidate shells recreated in page components, opacity-zero page entrances, and a broad mutation invalidation that refetches progress immediately after the server already returned it.
- Dashboard requests the complete analytics overview: seven SQL queries, including track/status breakdowns and a duration percentile unused by its four metric cards. Existing local test database measured in a READ ONLY transaction; raw aggregate timing data and EXPLAIN are saved separately. No records changed.
- Initial production build transiently failed in webpack prerendering; identical retry passed all 39 generated pages. No application fix was applied between these builds.

Measurement caveats: first development rubric measurements used an overstrict heading predicate and timed out despite a rendered Demo Mode notice; exclude these two samples. Initial production run stopped on a hidden mobile-link locator; its completed sidebar samples remain valid. The corrected complete run uses visible table rows. Development cache/compiler state and concurrent baseline build activity make cold before/after comparisons illustrative rather than controlled speedup claims. Production artifacts are rebuilt and measured independently.

Implementation priorities: immediate contextual transition feedback; retain existing content using router transitions and persistent candidate frame; remove redundant confirmed-progress fetch; trim dashboard aggregate work; add safe timing instrumentation, then repeat browser journeys and regression tests. Security guards, query ownership, interview state and official questions remain authoritative.
